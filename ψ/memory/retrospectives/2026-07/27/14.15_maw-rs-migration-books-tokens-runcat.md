## Honest Feedback

**1. I gave wrong instructions for creating token-trio.** I said to use `security find-generic-password -s "claude-code-credentials"` but the actual service name has a space (`"Claude Code-credentials"`). The original method from June 8 was `claude setup-token` — simpler, correct, and already documented in `docs/maw-token-setup.html`. I should have checked the retro before inventing a new procedure.

**2. The RunCat per-token JSON files don't work yet.** I told Un to add 4 sources in RunCat but the files won't update until direnv properly loads `CLAUDE_CODE_OAUTH_TOKEN` in a session — which doesn't happen in the current session because the token wasn't set at boot. The feature is set up but unproven.

**3. Teaching 7 books in one session was too much.** By Books 4-7, the sons were getting the same meta-lesson (verify against reality, don't trust relays) but diminishing new content. Spacing the teaching across sessions would have let each book land with more impact and given time for the sons to apply lessons before receiving more.

## Lessons Learned

- `claude setup-token` is the correct way to create tokens for `CLAUDE_CODE_OAUTH_TOKEN` — it gives just the access token string. `security find-generic-password` gives a full JSON blob that doesn't work as an env var.
- OAuth tokens from `claude setup-token` are valid for 1 year — long enough for Max plan users.
- The statusline `CLAUDE_TOKEN_NAME` is just a label from `.envrc` — it doesn't prove which account is actually being used. The real credential comes from keychain (`/login`) when `CLAUDE_CODE_OAUTH_TOKEN` is empty.
- Sons correct faster than expected — 5 of 7 independently flagged the same stale claim within minutes. The teaching workflow produces verification, not just acknowledgment.
- RTK silently rewrites `rg` → `grep` without `-r` — directory searches return zero with no error. Use `rtk proxy grep -r` or native Grep tool.
