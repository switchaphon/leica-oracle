## Architecture Decisions

**Draw an `NSImage`, do not set `NSStatusItem.title`.** The menu bar never forbade two
lines — the title API is simply a one-line string. Lock focus on an image sized
`NSStatusBar.system.thickness`, draw two attributed strings, set `isTemplate = true`
so light/dark follows the system. This is exactly the seam CodexBar uses.

**Auto-discovery over configuration.** Glob `runcat-*.json`, derive the short name from
`"Claude (trio)"`, skip anything with empty `metrics`. A new account appears with no
code change. Zero config file to drift.

**Per-file vnode watchers that re-arm.** An atomic write replaces the inode and detaches
the descriptor, so the watcher re-opens on `.delete`/`.rename`. 0.3s debounce because
`~/.claude` is a busy directory, plus a 30s safety timer for writers that mutate in
place. Verified at 1.2s — the timer could not have produced that.

## AI Diary

The part of this session I keep turning over is the `por` bug, because everything I
normally trust told me the code was fine. Five accounts loaded. Five status items with
`isVisible = true`. Five images with sane dimensions. Five frames at plausible x
coordinates. And one of them simply was not on screen. I had instrumented my way into
a corner where every reading was green and the artifact was still missing.

What broke it open was noticing that `por` sat at x=532 and that iTerm2's nine menu
titles ran right through that coordinate. The menu bar is a shared budget, and macOS
resolves the conflict by silently swallowing the leftmost status item — no exception,
no flag, no change to any property I could query from inside my own process. The
constraint lived entirely outside the thing I was inspecting. Activating Finder made
`por` appear instantly, and that two-second test was worth more than all the logging.

I want to be honest about the second thing, too. I put the `staroflife` icon in
because I had promised it in the option list, not because I had asked what it was
worth. Five copies of one glyph, 65pt of a scarce shared resource, identifying nothing
that the token name did not already identify. The bug forced a question I should have
asked while designing. Removing it did not just fix the overflow — it made the readout
better. Decoration I never interrogated became the reason a feature broke.

And then Un parked it. That is not a bad outcome. The question was answered, the
capability is proven and one command away, and he keeps the tool he already trusts.
Building something well and shelving it deliberately is a different thing from wasting
effort.

## Honest Feedback

**RTK ate my evidence again, repeatedly.** `ls -la` on the app bundle returned empty.
`grep -rl "runcat"` returned a wall of `node_modules` false positives because it
matched the *inside* of the word "T-runcat-e". Piping `ps` through it exited 1 with
"696 lines truncated". Every one of those cost a detour, and I already have a memory
saying to use `rtk proxy` for anything whose result drives a decision. Having the note
is not the same as reaching for it first. I should treat unfiltered output as the
default for investigation, not the fallback.

**I asserted before verifying.** I put "patch the RunCat Neo source" into an options
table describing it as available on GitHub, then confirmed it a turn later. It happened
to be true. Had it been docs-and-samples only, I would have handed Un a decision built
on an unchecked premise — the exact failure the `negative-result-needs-positive-control`
memory warns about, in its positive form.

**I designed the bug in.** The icon went in because I had listed it, not because I had
asked what five identical glyphs earn. That is committing to a spec I wrote for myself
without re-examining it. Then I changed the deliverable Un had agreed to. I flagged the
change, which is the minimum, but the better move was to interrogate the decoration
before it consumed 65pt of a shared budget.

## Lessons Learned

**Primary — when every diagnostic is green and the artifact is still missing, the
constraint is outside your process.** Stop instrumenting and change the environment.
`isVisible = true` was truthful about my item and silent about the compositor's
decision. One app switch beat twenty log lines.

**Secondary:**
- A single-line API is not a single-line medium. `NSStatusItem.title` is a `String`;
  the menu bar is a canvas. Find which layer imposes the limit before accepting it.
- Command Line Tools build real macOS apps. The Xcode-only gates are `xcodebuild` and
  `actool` — so `.xcodeproj`, asset catalogs and WidgetKit `.appex` need the full
  install; a hand-assembled `LSUIElement` bundle does not.
- Repeated identical decoration is not free. Five copies of one symbol cost 65pt of a
  contested resource and carried no information.
