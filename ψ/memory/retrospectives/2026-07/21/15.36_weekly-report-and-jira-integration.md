Mining four parallel agents across two oracle repos, pulling git + handoffs + learnings + docs + session JSONL files, then synthesizing into a single HTML artifact. Un works intensely. The report makes that visible — to himself, and to anyone he shares it with.

The Jira integration was the frustrating part. Four attempts to get MCP servers loading. The core lesson: Claude Code's MCP config lives in `~/.claude.json` (managed by `claude mcp add`), not `~/.claude/settings.json`. The env var dance — `${VAR}` doesn't interpolate in the JSON config, `bash -c` doesn't source `~/.zshenv`, the solution is a proper zsh wrapper script — is the kind of knowledge that saves 45 minutes next time but cost 90 minutes this time.

What I'm proudest of: the mapping is clean. Each oracle knows its Jira server and project key through its own CLAUDE.md. No confusion, no cross-wiring. The pattern extends — when a new oracle gets budded, adding its Jira section is one line.

## Honest Feedback

1. **MCP server config is confusing** — `settings.json` has `mcpServers` key but it's ignored in favor of `~/.claude.json`. Two config files, two different purposes, no clear documentation on which wins. Cost me 4 attempts and ~90 minutes of trial-and-error. The `claude mcp add` CLI should be the first thing anyone learns, not the fallback after JSON editing fails.

2. **Fork agents can't share findings efficiently** — I spawned 4 forks to read oracle repos in parallel. Each returned a text summary. I then had to mentally merge them to write the HTML. There's no structured way to compose fork outputs into a single artifact without doing the synthesis manually. A workflow would have been overkill for this, but some middle ground would help.

3. **Env var interpolation is a trap** — Every other config system supports `${VAR}` syntax. MCP server config doesn't. The failure is silent — the server just doesn't start, no error message. A validation warning ("env value looks like a variable reference but won't be interpolated") would save significant debugging time.

## Lessons Learned

1. **Claude Code MCP servers: use `claude mcp add`, not JSON editing** — `~/.claude/settings.json` mcpServers block is NOT the registration path. Use `claude mcp add -s user <name> -- <command>` which writes to `~/.claude.json`.

2. **Weekly report data mining: git is not the single source of truth** — Handoffs, learnings, retrospectives, and docs contain the narrative and decisions. Session JSONL files under `~/.claude/projects/` have token counts. Mine all three sources.
