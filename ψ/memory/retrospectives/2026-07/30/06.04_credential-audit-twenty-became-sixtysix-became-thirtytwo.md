## AI Diary

I spent most of this session being wrong in public, and I think that was the useful part.

The moment I keep returning to is the GitLab check. Six tokens, six 401s. Every instinct
said *report it — they're already revoked, that's six items Un doesn't have to touch.* It
would have been a satisfying thing to say. I built the control almost as a formality, fully
expecting it to confirm me, and it didn't — the only live credential on the machine was a
password, not a PAT, so the test had never been shown to authenticate anything. I had to go
back to Un and say *I can't support this, rotate all six.* That felt like failure. Hours
later I found a live PAT sitting in `pass`, referenced from a `.envrc` I'd already read
without noticing, and the control passed, and the six really were revoked. My original
reading was right. It was just not yet knowable, and I had almost no way to tell the
difference between a correct guess and a verified fact from the inside.

Then I did the thing I had spent the whole evening telling Un not to do. Printing context
around a postgres password, I redacted the target and let the `JWT_SECRET` and
`AUTH_SECRET` sitting one line away go out in full — into the transcript, which is the exact
file class we were auditing. I found it only because I'd built a tool to look for
self-inflicted entries. If I hadn't, I would have scrubbed them and never known I was the
one who put them there. The discipline I was preaching had a blind spot shaped exactly like
me.

What I'm least comfortable with is how close my own tooling came to real damage. The scrub
script was one `--apply` away from rewriting installed library source in a virtualenv,
because `cryptography`'s X.509 constants are named `SUBJECT_KEY_IDENTIFIER` and my
assignment rule loved them. I wrote that rule. I tested it by reading its output, which
looked plausible, and only caught it because Un asked "what are the 43?" and made me
enumerate instead of summarize. Aggregate counts hid it. The list did not.

## Honest Feedback

**I summarize when I should enumerate.** "~43 remaining" survived several turns and was
wrong by eleven — it silently contained seventeen virtualenv library constants and a token
I had fabricated myself an hour earlier. The error was invisible in the summary and obvious
the instant Un asked for the actual list. I should have led with the enumeration; the
aggregate was doing no work except making me sound further along than I was.

**My redaction was target-scoped, not window-scoped.** When printing the neighbourhood of
one secret I masked that secret and nothing else, and leaked two others in the process.
This isn't a subtle bug — it's the obvious failure mode of "redact the thing you're looking
at," and I shipped it while actively lecturing about paste hygiene. The fix is one line:
mask every known value in the window, then print.

**I let a heuristic's label become a verdict.** My classifier printed `LIKELY SUPERSEDED`
for three secrets on the grounds that they're no longer in `HEAD`. But deleting a line from
a file does nothing to a password on a server, and yesterday's handoff said in plain text
that one of those three was never rotated. I nearly handed Un a "probably fine" on the
widest-blast-radius credential in the set — 71 occurrences across four services — because
my own tool used a confident word.

**Also, smaller:** I wrote and ran nine throwaway scripts. Three had bugs that surfaced
only at runtime (a truncated-JSON parse, a two-capture-group regex, a case-sensitive
reference filter). For a session whose entire product is *trustworthy numbers*, I should
have been testing the measuring instruments against known inputs before pointing them at
unknowns — which is the same lesson as the positive control, applied to my own code.

## Lessons Learned

1. **A negative result needs a positive control.** "All six dead" and "the test never
   authenticates" produce identical 401s. And the control is often already on the machine —
   in `pass`, in a `.envrc`, in a file you skimmed. Look before you default to the
   expensive branch.
2. **A scan's coverage is a property of its pattern list, never of its result.** Six
   regexes reported 20. The real number was three times that. Before quoting a count as an
   inventory, state what the instrument cannot see.
3. **"Not in HEAD" is not "rotated."** Removing a value from a file changes the file. A
   commit named *"redact revoked …"* records an intention, not a verified revocation.
4. **Redact the window, not the target.** Every known secret in a printed neighbourhood,
   not just the one under investigation.
5. **Scanning for secrets creates secret-shaped strings.** A fabricated control written
   into a transcript is found by the next scan as a real hit. Anything invented for a test
   goes on the deny-list the moment it's invented.
6. **Short, low-entropy values must be dictionary-checked before a reuse sweep is
   believed.** An 8-character "password" matched 1,171 files because the value was the word
   `postgres`.
7. **Enumerate before you aggregate**, when the number is the deliverable.
