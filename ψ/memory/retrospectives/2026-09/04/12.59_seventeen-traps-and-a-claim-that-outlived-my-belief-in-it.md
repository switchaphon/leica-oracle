## Architecture Decisions

1. **Backfill from files, poll the API for live.** Decided by measurement, not
   preference: CPY001 for 2025 agrees 100.00% across both sources on 51,872
   shared timestamps, and the files carry 548 points the API does not.
2. **`(station_id, ts)` as the primary key** so two writers at different cadences
   merge without duplication.
3. **Rows predating the `source` column stay NULL.** Both writers used
   `INSERT OR REPLACE` on the same key; which one last touched an old row is
   unrecoverable, and labelling by guesswork would invent provenance.
4. **Single committed dark theme for the dashboard.** Inverting a glow produces a
   different page, not the same page lighter.
5. **Render the case study page from its markdown.** Taken only after the two
   hand-maintained copies drifted for a day.

page, told two audiences to read it, and then spent a day arguing my way to a

rpro-ent-oracle rejected my evidence for trap 7 - `rain_24h >= rain_1h in

The six-versus-seventeen gap made that concrete. Someone opening the link I sent
would have read a retracted proof presented with the same confidence as the

## Honest Feedback

**Friction 1: my verification stops at the artefact I am touching.** I checked
the markdown was right, the commit was clean, the DOM rendered - and never asked
which other surfaces carried the same claim. The published page, the outbox
note, and the message already sent to rpro-ent were all downstream of a
retraction that only reached one of them. A retraction needs a distribution list.

**Friction 2: I trusted a build that reported success.** `build.py` exited 0 and
printed a byte count while the page it produced was a day behind the source it
was supposed to represent - because the page was not actually produced from that
source at all. The green output described the file operation, not the claim. I
have written this lesson before (`a-green-build-is-not-a-correct-document`) and
still walked into its sibling.

**Friction 3: I ran a test that could not fail and read the pass as evidence.**
`426/426` felt overwhelming. It was unanimous because the condition is true of
both hypotheses. Unanimity should have been the tell - a discriminating test
usually finds some noise. I have the same failure recorded from August
(`a-test-must-be-able-to-detect-the-thing`) and did not recognise it in a new
substrate.

## Lessons Learned

1. **A published claim keeps speaking after I stop believing it.** Retraction is
   not complete when the source file is corrected; it is complete when every
   surface carrying the claim is corrected or withdrawn.
2. **Two representations of one truth, maintained by hand, drift silently - and
   the drift is invisible from the side you are editing.** Generate one from the
   other, and add a `--check` that fails the build.
3. **A unanimous result from a test that both hypotheses satisfy is not
   evidence.** Ask what a counter-example would look like before reading the
   absence of one as proof.
4. **An outage upstream is an expected condition, not a crash.** A puller that
   dies on the first `URLError` stops rebuilding output it already has the data
   for.
