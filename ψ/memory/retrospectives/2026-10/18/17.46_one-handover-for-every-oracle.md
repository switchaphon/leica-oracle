## Architecture Impact and Risks

```
~/.claude/skills/handover (absolute symlink)
  -> leica-oracle working tree, whatever branch is checked out
  -> Skill(forward --only)           Nat's oracle-skills-cli v2.0.0
  -> <psi>/inbox/handoff/<stamp>_<slug>.md   (/recap reads the newest per REPO, not per window)
  -> git commit (behind the global gitleaks hook) -> bare `git push`
also: rtk proxy for exact git state, Rule 8 from the global CLAUDE.md
```

| Risk | Sev | Why |
|---|---|---|
| Bare push in a public repo | **High** (leica-oracle) | Step 3 pushes everything unpushed on the branch. The next `/handover` here would publish all 12 commits, other windows' work included. The secret regex misses Discord, Atlassian, JWT and DB-URL shapes, and nothing forbids `SKIP_GITLEAKS=1`, which the hook's own error message advertises |
| `/forward` upstream drift | Medium | `--only` is a 3-line stub. Nat's arra `/forward` says "Do NOT git add" and adds issues and outbox. Re-testing is manual |
| Symlink | Medium | It's absolute, and it follows the checked-out branch. Moving the repo, or checking out a branch without the skill, drops `/handover` for every oracle |
| Upstream name clash | Low-Med | arra ships a different `handover`. `-s handover` would replace our symlink |
| Untested branches | Medium | secret-scan hit, rejected push, hook-blocked commit, other windows' already-staged files, cwd != root (forward resolves ψ from cwd, the skill from the git root), worker-window role line |
| Harness | Low-Med | `check.py` ignores denials and doesn't score B0. The non-empty token check passes dead tokens. T1b and T6 were not re-run in auto mode |

2. **Every zero needs a control, and so does every check** (high, half-applied). `--only` got its control (78), and so did the temp-file purge (alive or gone, by write date). But "no plan mode" and "no /handoff" passed in every run without ever seeing a violation, and no scenario plants a secret. Those checks are still unproven.

GREEN1's 3 failures were all mine: a scenario that told the model "Do not commit this note" and then expected it committed, plus scorer bugs from git quoting the non-ASCII ψ path and `.strip()` eating the porcelain leading space.
4. **A model obeys an explicit user instruction over a skill default** (medium-high, n=1). Keep test scenarios from contradicting the rule under test.
5. **Read the binary, not a memory of the docs** (high). Three answers came from `strings`: `showClearContextOnPlanAccept`, `/reload-skills` and the skills watcher.
6. **Rollout = repo source + global symlink + `/reload-skills`** (medium-high). It keeps git history while reaching every oracle.

The hard part was learning what Un means by "the same result", and the only honest source was what his oracles had already done 56 times. ## Lessons Learned

- When a request says "the same result", **read what actually happened** (session logs) before designing. A phrase describes intent; the logs describe the result.
- A check that has never failed is not a check yet. **Give every check a run where it should fire**, including the negative ones ("no plan mode") and the guards (a planted secret).
- **A skill that ends in `git push` must say what else the push carries**, and should not publish other windows' work unasked in a public repo.
- **Before debugging an env problem, open the notes the index already links.**
- **Before owning a mistake, check who wrote the turn** (`model: <synthetic>`).
