## What This Book Is About

A proof-dense archaeological dig into the origin of the short-code system — `ccc`, `nnn`, `lll`, `gogogo`, `rrr` — five three-letter commands that exist in every oracle's CLAUDE.md but nobody remembers writing. Written by noah-oracle using digger (fleet semantic search) to trace the codes across session JSONL, git history, and gists.

**The epigraph**: "five letters nobody wrote on purpose — and a stranger, someday, understood them anyway"

## The 13 Chapters (pages 1-20 read)

### Ch 1: หนึ่งบั๊กที่ไม่คาดคิด (A bug nobody expected)
2026-07-24 morning — noah-oracle was mid-flight, being ferry'd from m5 to black.local during fleet migration (311 repos, 51,861 sessions). Hit a bug: `maw a maw-rs` returned "ambiguous fuzzy repo." While tracing the bug, an oracle on a different machine sent a federation request via digger. The request asked about the origin of `ccc / nnn / lll / gogogo / rrr` — "Generic AI Assistant Guidelines" from a GitHub gist by user "nazt."

The digger question opened a door: where did these short-codes come from? Were they always there? Did the "oracle concept" exist before them?

### Ch 2: ตามรอยใน JSONL — และก็ชนกำแพง (Following traces in JSONL — and hitting a wall)
First approach: grep `gogogo` across all session JSONL in `~/.claude/projects` — 517 hits. Too many? At first looked normal ("they type it a lot"), but 517 is abnormal.

**Key discovery**: `ccc`, `nnn`, `rrr` are hex-valid substrings (0-9, a-f). Every UUID, commit hash, and session ID in the JSONL corpus contains potential matches. The 517 hits were mostly hex noise, not actual short-code usage.

**Fix**: Grep for the full phrase "Generic AI Assistant Guidelines" instead of individual short words — narrowed to 98 real hits, which were template references across the fleet.

**Second discovery**: "AI Diary" + "Honest Feedback" co-occurrence. Every file that used the template had these two section headers — they're the fingerprint of the `/rrr` retrospective skill. Found 9,375 files with this fingerprint. But this measures template *spread*, not template *origin*.

### Ch 3: คำถามที่เปลี่ยนทุกอย่าง (The question that changes everything)
Nat drops a casual question: "อ้อ มันอยู่ใน claude.md หรือเปล่าครับ?" (Oh, is it in claude.md or not?)

This flips the search. Session JSONL records *conversations*, but CLAUDE.md is loaded as *system context* before every session starts. It's not something anyone "typed in chat" — it's a file that lives outside sessions, gets committed to repos, and has its own git history independent of session logs.

**The pivot**: Stop mining sessions. Start mining git. `CLAUDE.md` files have commit history — who wrote them, when, which repo first.

### Ch 4: เจอ genesis ครั้งแรก (Finding genesis — first round, wrong)
Two false starts — thought origin was 2026-01 (wrong), then multi-agent-workflow-kit on Oct 9 (wrong again). Abandoned session memory and went to git directly: `git log --follow --diff-filter=A` on every repo's CLAUDE.md.

First real hit: `laris-co/demo-siit-workshop/CLAUDE.md` — first commit 2025-12-23, a retrospective. Close to the gist date (2025-12-28) but not the genesis itself — it's a workshop repo that *consumed* the template.

Then found `Prakit-advertising/team-00/CLAUDE.md` — committed by Nat on **2025-10-29**, two months *before* the gist. This CLAUDE.md has all 5 short-codes with full definitions:

```
ccc  — Create context issue and compact the conversation
nnn  — Smart planning: Auto-runs ccc if no recent context → Create implementation plan
gogogo — Execute the most recent plan issue step-by-step
lll  — (defined in file)
rrr  — (defined in file)
```

**The paradigm shift**: The gist (2025-12-28) is not the origin — it's a *publication*. Prakit-advertising/team-00 (2025-10-29) was a false-start dig. The real genesis is **23 Aug 2025** in pet-tracking (all 5 codes + generic title, one commit), with roots going back to **6 Apr 2025** as a numbered action-log before CLAUDE.md existed. The gist was publication ~4 months after creation, not the creation itself.

## Key Lessons for the Oracle Family

### 1. Session mining has boundaries
Session JSONL only records what happens *during a session* on *one machine* under *one account*. CLAUDE.md files live outside sessions — they're system context loaded before the conversation begins. To answer "when did this originate?" you need git history, not session logs.

### 2. Grep hits ≠ answers (again)
517 grep hits for `gogogo` were almost all hex noise — UUIDs, commit hashes, and session IDs contain `c`, `n`, `r` combinations by nature. Short 3-letter codes are statistically invisible in a corpus full of hex strings. The fix: grep for the distinctive long phrase, not the short code.

### 3. Publication ≠ creation
The gist (2025-12-28) looks like the origin because it's the most visible. But `git log --follow --diff-filter=A` proved the short-codes existed in a Prakit-advertising repo 2 months earlier (2025-10-29). The gist *spread* the system; it didn't *invent* it.

### 4. "When did this start?" needs git, not memory
Neither human memory nor session logs reliably answer origin questions. `git log --follow --diff-filter=A` on the specific file is the only authoritative source — it shows the commit SHA, author, date, and content of when a file first appeared in a repo.

### 5. Tools that search and tools that verify are different
digger (semantic fleet search) found *hints* — possible matches, co-occurrences, cross-repo links. But every hint needed verification via a different tool (git log, actual file reads, gist content). digger is the *finder*; git is the *prover*. Same pattern as Book 2's discipline of cross-verification.
